# 구현 순서

1. DenseNet121 모델 인계
   실제 checkpoint, 모델 생성 코드, 입력 전처리, 출력 변환, 학습 라이브러리 버전 확보.
   PyTorch인지 TensorFlow/Keras인지 확인: 현재 설계는 PyTorch 제안이며 실제 형식이 다르면 추론 계층만 변경.
   같은 이미지의 학습 환경 예측값을 기준 결과로 보관.
2. 로컬 추론
   서버와 독립적인 단일 이미지 predictor부터 구현.
   같은 모델·전처리·장치 조건에서 기존 예측과 허용 오차를 정해 비교.
3. API
   실제 모델 연결 후 업로드 제한/오류/모델 준비 상태 검증.
4. 파일 업로드 화면
   미리보기 → 분석 → 점수 → 다른 사진 선택 흐름 완성.
5. 카메라
   권한 허용/거절, 촬영/재촬영, 모바일 회전, track 종료 확인.
6. 통합
   업로드와 카메라에서 같은 이미지 바이트를 보내면 동일 점수인지 검증.
   한글 파일명, 손상 파일, 과대 이미지, 동시 요청, 모델 없는 경우 검사.
7. 배포 및 측정
   HTTPS에서 모바일 카메라 확인. 예열 전후 지연시간과 메모리 기록.

tests/unit: 전처리·출력 변환·파일 검사
tests/integration: 정상 업로드·오류 계약·readiness
tests/e2e: 파일/카메라 UX, 결과 표시

완료 조건: 실제 DenseNet 점수 반환, 기존 추론과 일치, 파일/카메라 사용 가능,
모델 및 입력 오류에서 가짜 점수를 내보내지 않음, 원본 이미지 임시 리소스 정리.
